# 2026-10-28 — P(-1) audit and repairs (1.1.0 → 1.1.1)

**hapi version**: scanned at **1.1.0** (cyrius 6.7.18), repaired in **1.1.1**.
**Auditor**: maintainer pass per CLAUDE.md Process P(-1), with three
independent read-only streams run against a frozen snapshot of the released
1.1.0 tree: a per-architecture constant sweep (which also booted a **real
agnos 1.57.14 kernel** in QEMU), a write-path security re-walk, and external
research. Every stream finding was re-constructed by hand against a real
build before a repair landed.
**Trigger**: thirteen fixes across 1.0.9 / 1.0.10 touched a path argument,
a syscall and the audit-trail write path — all three of CLAUDE.md's re-run
triggers — and 1.0.12 touched a syscall again. The previous pass,
[`2026-08-25-audit.md`](2026-08-25-audit.md), scanned 1.0.5.

> ⚠ **This pass found the capability boundary open again.** The 2026-08-25
> pass established that the earlier lens checked validators and not writers.
> This one shows a third gap: 1.0.8 decided containment on the *resolved*
> path, but only for the scope, only at plan time, and with `..` collapsed
> *before* symlinks were followed. The four HIGH findings (F-045, F-051,
> F-052, F-054) and F-057 are one idea — a path judged on its spelling, or
> before it existed, where the kernel acts on where it goes. F-002, recorded as closed
> at 1.0.8, was live for `--root` (F-051).

## Scope

All six P(-1) steps, the four standing threat classes (path traversal,
symlink loops, TOCTOU, capability scope), and the roadmap's 1.1.1 items:
the repaired write paths of 1.0.9 / 1.0.10 / 1.0.12; aarch64 as a
first-class target, with a sweep of every numeric constant for per-arch
meaning; the two accepted boundaries of 2026-08-25 that were never written
down; ADR 0001's `---` rule; and six repair candidates found during the
1.0.12 / 1.1.0 toolchain work.

## Method

Same bar as 2026-08-25: a finding is accepted only with a **constructed
failure** — concrete inputs, a real build, a stated wrong outcome. Each
repair was **mutation-proven**: its regression test was run against the
reverted code and confirmed RED (for F-049, the old probe *hangs* the
suite; confirmed with a timeout). Two exceptions are stated where they
occur: F-039's atomic half cannot be staged deterministically in one
thread, and F-059 needs a real agnos kernel.

The agnos target was exercised three ways: under mirshi (all agnos code
paths, via the new `tests/agnos.tcyr`), on a real 1.57.14 kernel booted in
QEMU (by the arch sweep), and by reading the kernel source. **mirshi differs
from the kernel on four calls** (see *Harness gap*) — two findings below
were visible only on the kernel.

## Findings

Severity is the 2026-08-25 scale. All are **FIXED in 1.1.1** unless marked.

### Retroactive — fixed before this pass, never given an id

| ID | Sev | Summary |
|----|-----|---------|
| F-035 | LOW | `hapi_open_nofollow` carried the x86_64 `O_NOFOLLOW` literal (131072), which is `O_LARGEFILE` on arm64, so the aarch64 build followed symlinks there from 0.9.0 to 1.0.11 and F-003's defence was absent. ### The capability boundary

**F-051 — `--root` through a symlink escapes `$HOME` with no grant [HIGH].**
`cap_check_root_r` compared spellings, so `--root ~/trap` with
`trap -> /outside` passed as "within `$HOME`". Every later check then
resolved *both* the target and the scope root through `trap`, found the
target contained, and linked into `/outside`; `--force` deleted
`/outside/.zshrc`, replacing it with the symlink. *Fix*: the grant is decided
on the physically resolved root against the resolved `$HOME` and resolved
allowlist entries; the returned spelling is unchanged, so trail shape is too.

**F-052 — the resolver collapsed `..` before following symlinks [HIGH].**
`fsl_resolve_path` lexically normalized first, popping `..` against the
literal name before it. `a/..` with `a -> /outside/deep` came out as the
directory holding `a`; the kernel goes to `/outside`. `adopt 'a/../c.conf'`
moved a file from outside `$HOME` into the package (and recorded a target
the parser itself rejects). *Fix*: `.` and `..` are walked against the
resolved prefix, and a symlink's text is spliced in raw. adopt also refuses a
`..` component outright — a `[[link]]` target cannot hold one.

**F-054 — adopt of a granted path outside the scope root: SIGSEGV or a garbled row [HIGH].**
The row's `target` was sliced off `abs_target` at `strlen(scope_root)` with
no check that the prefix was there. Shorter than the root: a negative
length, `alloc` → 0, a store before it — exit 139. Longer: a target with its
first bytes chopped, written to the manifest and the trail. *Fix*: refused —
a file outside the scope root has no target to record. The scope root is
normalized before the slice.

**F-045 — a target that resolves into the package [HIGH].**
Containment was asked of the scope, never of the package. With
`~/.ssh -> dotfiles/pkg/ssh` and a row `ssh/config -> .ssh/config`, the
target *is* the row's source. `link` called it an "existing regular file";
**`link --force` deleted the user's only copy** and planted a symlink to
itself, `linked 1 / 1`, exit 0. `adopt ~/.ssh/config` moved the package's
file to a second name and left a dangling link inside the package.
(Research: dotbot #360, the same bug, fixed there in v1.22.0.) *Fix*:
`fsl_lands_in` — the target's parent resolved, its final name not followed —
refuses on `link` (all modes) and `adopt`; `--force` does not override.

**F-057 — a row beneath another row's target escapes at execute time [MEDIUM].**
Containment is planned for every row before any is written. Rows `.x` and
`.x/inner` were both absent, so both looked contained; row 1 then planted
`.x -> pkg/escape` (a package symlink to `/outside`) and row 2 was written
*through* it into `/outside`, exit 0. *Fix*: a target beneath another row's
target is refused. Even without an escape such a row writes into the
package through hapi's own link; no layout needs it.

**F-047 — `/` contained nothing [MEDIUM].**
Both prefix matchers skip their trailing-slash strip for `/` (it would empty
the prefix) and then demanded a second `/` at `path[1]`. `--root /` with
`HAPI_ALLOWED_ROOTS=/` refused every row, and agnos — which stages
`HOME=/` — refused every row of every verb (seen on the real kernel). *Fix*:
`/` contains every absolute path.

### Link shape and classification

**F-046 — link text from the lexical parent [MEDIUM].**
ADR 0003's link text was computed from the target's *spelled* parent. With
`~/.config -> data/deep/config`, `.config/rc` got `../dotfiles/pkg/rc`,
which resolves from `~/data/deep/config` to nothing. `link` reported
success, `status` said OK (it compares text), a re-run said up to date.
*Fix*: computed from the parent the link physically sits in (the source half
stays lexical, per ADR 0003's portability rationale). Byte-identical for
every target without a symlinked parent. `unlink` / `rollback` still accept
the old text, so links an older hapi planted stay removable.

**F-053 — a `./` target dangled, reported OK [MEDIUM].**
`target = "./.zshrc"` kept its `.` in the lexical parent, so the text
climbed one directory too far. Fixed by F-046 for `link`; adopt's `<file>`
is now normalized (`.` and `//` only — `..` is refused).

**F-049 — `link_probe` hung on a FIFO and misread unreadable directories [LOW].**
File-vs-directory was decided by `open(O_RDONLY)` + `getdents`. A FIFO at a
target blocked the open forever (`link`, `status`, `--dry-run` all hung). Any
failed open read as FILE, so a mode-000 or mode-0300 directory was a "file"
— and `adopt` then moved that **directory tree** into the package, exit 0.
*Fix*: classified with `stat`, which needs neither an open nor read
permission.

**F-050 — agnos `link_probe` called every stat failure ABSENT [LOW].**
agnos returns a bare -1, so a path through a regular file read as absent
where Linux says ENOTDIR. `unlink` then reported such an entry removed,
wrote no trail entry, and `list` kept counting it live. *Fix*: absent only
when the nearest existing ancestor is a directory.

### Write paths and reporting

**F-055 — unlink / rollback / adopt mutated before proving the trail writable [MEDIUM].**
F-018's preflight reached `link` only. With a torn tail, `unlink p` removed
all three symlinks and recorded none ("unlinked 0 / 3"); with an unwritable
trail, `adopt` kept its move + link + row and `rollback` later said the trail
was empty. *Fix*: all three preflight before their first mutation.

**F-056 — rollback without a marker was not idempotent [MEDIUM].**
The window was the whole trail, including entries a previous rollback
appended, so each run re-reversed the last: 1, 2, 4 … 512 reversals and a
trail doubling per run, against the guide's "a second run … does nothing".
*Fix*: a clean rollback that changed something closes its window with a
`rollback-marker` (the entry `checkpoint` writes). Format unchanged.

**F-038 — rollback reported a failed manifest rewrite as "row not found" [MEDIUM].**
Every removal failure printed "manifest row not found" and the verb exited
0. When the rewrite itself failed — reproduced with a crashed run's
`hapi.cyml.<pid>.tmp` holding this pid's name — the row stayed, its source
had just left the package, and the run said `rolled back 1 / 1`. *Fix*: only
`RowNotFound` is a warning; anything else names the reason and exits 1. The
writer now says when a staging leftover is in the way, `adopt` prints the
writer's reason, and `check` lists leftovers. Under mirshi every agnos child
is pid 1, which makes the leftover collision likely there, not rare.

**F-037 — `check` passed an unlistable package [MEDIUM].**
`dir_list` answers an empty vec for a directory it cannot read. Mode 0311
still opens the manifest by name, so the F-028 orphan walk saw nothing and
`check` said `ok`, exit 0, with an orphan present. *Fix*: `dir_list_checked`;
a failed listing is an error.

**F-048 — `check` used its own source predicate [LOW].**
It tested ABSENT alone; `link` and `status` share `fsl_source_present`, which
also refuses ERROR. A source through a regular file (`f/sub`) passed `check`
and was refused by `link`, whose message sends the user to `check`.

**F-058 — a symlinked `hapi.cyml` was replaced by a copy [LOW].**
The rewrite renames a staging file over the manifest, so a package whose
`hapi.cyml` linked to a shared manifest got a private copy holding the new
row; the shared file never saw it. *Fix*: refused, by the writer and up
front by `adopt`. (Research: python-dotenv GHSA-mf9w-mj56-hr94, same shape.)

**F-041 — appending to a CRLF manifest wrote LF lines [LOW].**
`adopt` left mixed endings. Matching the ending needed the remove's
blank-line trim to understand CR too — otherwise each adopt → rollback
would have grown a blank line. (1.1.0's rollback was byte-exact by
accident; the hypothesis that it grew was refuted.) CRLF manifests now get
the same tidy-up LF ones always had.

### agnos

**F-044 — an absent trail was refused as unreadable [LOW].**
F-017's "no trail yet is empty" keyed on `-ENOENT`, which agnos never
returns. `list`, `unlink` and `rollback` exited 1 on a first run, "audit
trail exists but could not be opened" (real kernel and mirshi). *Fix*:
`hapi_open_absent` asks stat on agnos.

**F-039 — F-031's residual race closes; the pre-check missed long links [LOW].**
The agnos arm now passes `O_NOFOLLOW` (bridged to `AO_NOFOLLOW`, kernel
≥ 1.56.53), so the refusal is atomic. Kernels older than that ignore the bit
— open#7 has no flag validation (read at 1.56.52) — so no minimum kernel is
needed and the readlink pre-check stays for them. The pre-check's buffer was
64 bytes, and agnos readlink answers **-1** for a body that does not fit, so
any link body ≥ 65 bytes read as "not a symlink" and `hapi_backup_copy`
snapshotted the link target's bytes (real kernel; **mirshi truncates like
Linux and hid it**). Now 4096, the agnos maximum. *Not mutation-provable*:
the race cannot be staged in one thread; the test pins the primitive.

**F-040 — agnos `O_EXCL` [INFO].** Neither exclusive create relied on the old
behaviour; both were written assuming exclusivity. On agnos builds before
1.0.12 (cyrius < 6.6.4) and kernels before 1.56.56 they were plain
non-truncating opens, so a leftover staging file longer than the new
manifest left its tail in the renamed result. Now pinned on the target
(refuses, content intact, `O_TRUNC` too).

**F-059 — adopt cannot succeed on a real agnos kernel [MEDIUM] — ACCEPTED, kernel gap.**
Three independent blockers, found on 1.57.14 in QEMU: the package-dir lock
opens a directory without `AO_DIRECTORY` (-1); agnos flock#59 accepts only
ext2 regular-file fds (-1 on a directory); and ext2 rename refuses an
existing destination, so no atomic manifest replace exists. It fails
closed — "manifest edit failed; filesystem restored", the file back in
place. The first two are hapi-side and cheap, but the third leaves nothing
to gain from them. Tracked in
[`../development/issues/2026-10-28-adopt-on-agnos-kernel.md`](../development/issues/2026-10-28-adopt-on-agnos-kernel.md).

### Supply chain and CI

**F-042 — CI fetched the toolchain installer from `main` [MEDIUM].**
Both workflows piped `…/cyrius/main/scripts/install.sh` into `sh`, so a push
to upstream's mutable branch ran on every hapi build despite the pinned
version — and that script is the one doing the SHA256 and signature checks.
`curl | sh` also exits 0 when the fetch fails. *Fix*: fetched from the pin's
tag to a file, then run (upstream's `cyriusly` did the same at 6.2.30 /
6.6.20). Verified byte-identical to the local 6.7.18 tag.

**F-043 — CI never executed hapi's agnos code [MEDIUM].**
The smoke step looked for a mirshi the runner never had, got SKIP every run,
and only warned; cyrius 6.7.16 had dropped upstream's own mirshi gates.
*Fix*: `scripts/build-mirshi.sh` (pinned tag, built with hapi's toolchain —
mirshi 1.11.3's tracked `lib/` does not build from a clean clone), the new
target-neutral `tests/agnos.tcyr` (55 assertions; runs under `cyrius test`
on x86_64 and aarch64 too), and a smoke that fails on any non-zero exit,
SKIP included. The recipe was run end to end from a fresh https clone.

### Hardening without a constructed failure

- The trail append ignored `file_lock`'s return. On agnos the lock *is* the
  append's atomicity (no `AO_APPEND`), and flock#59 can fail (a non-ext2 fd;
  a full 16-slot table). Now refused rather than attempted. Not
  constructed — needs a ZFS-backed trail or a full lock table.

## Harness gap — mirshi is not the kernel

The same agnos binary, run both ways by the arch sweep:

| Call | real agnos 1.57.14 | mirshi 1.11.3 |
|------|-------------------|---------------|
| readlink#70, 86-byte body, 64-byte buffer | -1 | 64 (truncates) |
| open#7 on a directory without `AO_DIRECTORY` | -1 | an fd |
| flock#59 on a directory fd | -1 | 0 |
| rename#31 onto an existing file | -1 | 0 (replaces) |
| `HOME` / `PWD` | `/`, `/` | unset |

So CI's agnos run cannot see F-039's long-link half or F-059, and the real
default environment (F-047) only by construction in `tests/agnos.tcyr`. The
divergences are mirshi's to fix; until then a P(-1) pass that touches the
agnos arm should repeat the QEMU run.

## Accepted boundaries

- **F-059** — adopt on a real agnos kernel (above), until the kernel can
  rename over an existing file.
- **`hapi checkpoint` is not idempotent** (from 2026-08-25): three runs
  append three markers. Now stated in
  [`../guides/checkpoint.md`](../guides/checkpoint.md). Rollback (F-056) now
  appends markers too, so consecutive markers are normal and cost one line.
- **The writer-side torn-tail refusal** (1.0.9, from 2026-08-25) is now in
  ADR 0002's *Crash semantics*, with the PIPE_BUF claim there corrected.
- **`source = "."` links the package root.** Odd, not destructive; rejecting
  it would tighten the frozen ADR 0001 schema.
- **NFS** (unconfirmed — no NFS here): flock on NFS is emulated with fcntl
  locks and an exclusive lock needs a writable fd, but the manifest lock is a
  directory fd, so `adopt` likely fails closed on an NFS home.
- **The agnos residual race** survives only on kernels older than 1.56.53.
- Every 2026-08-25 boundary not listed here still holds.

## Refuted

Recorded so a future pass does not re-derive them: a relative
`backup_path` in the trail (ADR 0002 requires absolute paths only for
`abs_source` / `abs_target`); a relative `XDG_STATE_HOME` (user
misconfiguration under the XDG spec); `--root ""` (exit 2, correctly sized
message); trailing `/` or `/.` targets (still refused, F-032); a
same-second `--backup-to` collision (F-010's suffixing and `O_EXCL` hold);
a link-side loss from a genuine mid-write crash (refused correctly — only
the reversal verbs lost, F-055); an adopt `--backup-to` race on derived
source names (the package lock serialized it; unconfirmed rather than
refuted); 1.1.0's CRLF rollback growing blank lines (it was byte-exact);
`--force` removing a directory, `$HOME` included (it never does); a `sync`
that applies some rows before a conflict (all rows are planned, and a
conflict refuses before any write); stow's `--adopt` overwriting package
content (hapi refuses an existing package-side name).

## External research (Step 4)

GNU stow has had no release since 2.4.1 (2024-09). Nothing new since
2026-08-25 among dotfile-manager advisories (no CVEs or GHSAs for stow,
chezmoi, yadm, dotbot, rcm, homeshick or home-manager since 2025). What the
older material contributed, all checked against a build:

- dotbot #360 (a target resolving to its own source through a symlinked
  parent) → **F-045**.
- chezmoi 2.72.0's path rejections (`""`, `.`, `..`, `a/..`, …) → hapi's
  parser already rejects `..` anywhere and empty values; `source = "."`
  accepted (above).
- python-dotenv GHSA-mf9w-mj56-hr94 (rename-based writes and symlinks) →
  **F-058**.
- stow #139 (an interrupted unfold) and home-manager's preflight → hapi
  plans every row before writing and refuses before any change (refuted
  above); F-055 extends the trail preflight to every mutating verb.
- flock(2) / open(2) man-pages 6.19 → the NFS boundary above; the trail's
  lock fd is `O_RDWR` (fine), the manifest's is a directory fd.

## Sign-off

Twenty-five findings (F-035 – F-059): two retroactive, twenty-two fixed in
1.1.1 with mutation-proven tests (F-039's atomic half excepted, as stated),
one accepted (F-059). The v1.0 contract is intact: the command surface, ADR
0001's schema and ADR 0002's line shape are unchanged. Two observable
behaviours change, both as fixes. Rows that would write into the package
or through another row are refused. Links under a symlinked parent get
text that resolves, and links an older hapi planted there stay removable.
The honest reading is the 2026-08-25 one, one level down: the resolved-path
boundary of 1.0.8 was real but partial, and
the next pass should start from the question this one kept asking — *where
does the kernel put this, and did hapi check that, at the moment it writes?*
